# 开发路线

## V0.1：三维潜水基础

已建立第三人称游泳、潜浮、冲刺、瞄准捕鱼、海底采集、氧气风险、装备升级与存档。历史验证记录见 [TESTING.md](TESTING.md)。

## V0.2：海岸餐厅成长

本轮范围由 [餐厅需求基线](RESTAURANT_REQUIREMENTS.md) 定义：正常返航入库、售货筹资、六项可见装修、三种料理、顾客订单、暂停/打烊、经营记录和旧档兼容。最低 210 G 基础装修即可开业，后续家具带来实际经营效果。

完整验收路径为“空档出航 → 入库 → 出售 → 基础装修 → 留鱼备菜 → 制作/上菜 → 账单 → 再次出海”。是否通过以 [A01–A16 验收记录](RESTAURANT_ACCEPTANCE.md) 的实际证据为准。

## 下一步：打磨现有循环

1. 根据试玩调整鱼群密度、氧耗、首店筹资时长与营业节奏。
2. 完善新手指引、物资入库回顾、料理与装修反馈。
3. 补充海底环境声、餐厅氛围声和音乐。
4. 加强三维场景地标、顾客动作和图鉴。
5. 增加存档管理与更完整的键盘/手柄操作。

## 后续扩展

在当前循环稳定后，再评估自由家具布局、厨师与服务员、烹饪小游戏、菜谱研发、订单需求变化、剧情角色和多个海域。采购、腐败、租金、天气节日及联网不纳入 V0.2。

## 每次发布需保留的检查

- 潜水、餐厅、暂停与码头之间切换正确。
- 库存、菜单预留、收入、退料与日期没有重复计算。
- 余额不足、前置缺失、满背包、低氧和订单超时有明确反馈。
- 新旧档、异常档与营业中断可安全恢复。
- 测试和截图使用隔离进度，不修改真实玩家档。
- 实际查看旧店、装修、营业、账单和潜水画面，检查中文与窗口缩放。
- 项目缓存、日志、存档、临时文件和验证产物保留在项目内。
